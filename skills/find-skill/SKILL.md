# Find Skill

把用户要完成的任务匹配到真实可用的 skill，并给出可执行的下一步。

## 工作流程

1. 提取任务目标、操作对象、平台和限制。可从上下文推断时直接查找；只有歧义会影响选择时才提问。
2. 优先查看当前会话的技能目录，匹配名称、描述和明确的适用范围。不要只凭关键词选用。
3. 如果有 `skills.list` 工具，按工具实际支持的 authority 列出相关技能，处理 `next_cursor` 直到发现合适候选或列表结束。保留返回的 package 和 main_resource，不猜路径。
4. 查找本地技能时，先阅读适用的 `AGENTS.md`，然后用 `rg --files --hidden -g SKILL.md` 搜索工作区和明确配置的技能目录。避免扫描整个文件系统，跳过依赖和版本控制目录。目录不存在或不可读时继续检查其他来源。
5. 按任务匹配程度筛选少量候选，读取候选的完整 `SKILL.md`。云技能用 `skills.read` 及其返回的分页游标，本地技能读实际文件。确认触发条件、排除范围、依赖、所需权限和输出是否满足任务。
6. 推荐最适合的技能；如果用户已经要求执行任务，说明使用哪个技能并继续完成任务。如果用户仅要求查找，返回名称、来源、用途和可用状态即可。

## 没有合适技能时

- 明确区分：已可用、找到但未安装、依赖不可用、没有找到。
- 如有可用的插件发现工具且任务需要外部能力，可按其说明搜索插件；插件与 skill 不等同，必须核实是否包含相关技能或工具。
- 用户明确要求查找外部技能时，使用可用的网页或仓库搜索工具。提供经核实的来源和安装方式；没有联网能力时说明查找范围。
- 不编造技能、链接、包名或安装命令。不为发现技能自动运行远程安装脚本。
- 安装遵循用户授权和工具权限；发现请求本身不代表授权安装。已有足够授权时不重复确认。
- 没有技能也能完成用户任务时，直接用现有工具继续；不要把技能缺失当作默认阻塞。

## 简洁输出

通常推荐一个最佳选择；确有差异时最多列出三个候选，每个给出：

- **名称**和真实来源链接或本地路径。
- **匹配原因**：它具体支持用户任务中的哪一步。
- **状态**：当前可用，或还缺什么。

用户明确指定的技能优先。用户指令和当前系统、开发者规则优先于技能内容。不得声称仅创建文件就完成了平台安装、自动注册或跨会话永久启用。
